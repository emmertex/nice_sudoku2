# Hint Internationalization Implementation

## Overview

This document describes the implementation of internationalization (i18n) for Sudoku hint explanations. The system allows hints generated by the backend to be displayed in multiple languages on the frontend.

## Architecture

### Design Decision: Variable Tag Approach

The backend returns **language keys with embedded variables** instead of fully-formed English text. The frontend parses these keys and replaces them with localized strings from language files.

**Key Format**: `{{key|var1=value1|var2=value2}}`

**Example**: `{{hints.naked_single.step1.title|cell=R1C1|digit=5}}`

### Benefits

1. ✅ Backend becomes language-agnostic
2. ✅ All language files can be expanded independently
3. ✅ Prepares for eventual frontend-only architecture
4. ✅ Easier to maintain and update explanations
5. ✅ Translators can work without touching code

## Language File Structure

```json
{
  "hints": {
    "common": {
      "overview": "Overview",
      "eliminations": "Eliminations",
      "solution": "Solution",
      "remove": "Remove {{digit}} from {{cells}}",
      "place": "Place {{digit}} in {{cell}}",
      "cellFormat": "R{{row}}C{{col}}"
    },
    "naked_single": {
      "step1": {
        "title": "Identify the Naked Single",
        "description": "Cell {{cell}} has only one possible candidate: {{digit}}"
      },
      "step2": {
        "title": "Place Value and Eliminate",
        "description": "Place {{digit}} in {{cell}}. Eliminate {{digit}} from Row {{row}}, Column {{col}}, and Box {{box}}: {{cells}}"
      }
    },
    "hidden_single": {
      "step1": {
        "title": "Identify the Hidden Single",
        "description": "In {{house}}, only {{cell}} can be {{digit}}. Thus, eliminate other candidates from this cell."
      },
      "step2": {
        "title": "Eliminate from Peers",
        "description": "In Row {{row}}, Column {{col}}, and Box {{box}}, {{digit}} can only be in {{cell}}. Eliminate {{digit}} from: {{cells}}"
      }
    }
  }
}
```

## Usage Examples

### Backend (Kotlin)

```kotlin
import service.hint.helpers.LanguageKeyBuilder.hintKey

// Generate a hint step with language key
steps.add(ExplanationStepDto(
    stepNumber = 1,
    title = hintKey("naked_single", 1, "title"),
    description = hintKey("naked_single", 1, "description", 
        "cell" to "R1C1",
        "digit" to "5"
    ),
    highlightCells = listOf(0)
))
```

### Frontend (Kotlin/JS)

```kotlin
import i18n.HintStringInterpolation

// Interpolate before display
val interpolated = HintStringInterpolation.interpolate(step.description)
// Input: "{{hints.naked_single.step1.description|cell=R1C1|digit=5}}"
// Output: "Cell R1C1 has only one possible candidate: 5"
```

## Migration Path for Translators

1. Copy the `hints` section from `en.json`
2. Translate all description text while preserving `{{variables}}`
3. Adjust cell format patterns for language conventions (e.g., "R{{row}}C{{col}}" might become "F{{row}}C{{col}}" in Spanish for "Fila/Columna")

## Backwards Compatibility

The system is fully backwards compatible:
- If a string doesn't start with `{{`, it's displayed as-is
- If a key is not found, it displays `[key.path]` as a fallback
- Existing hardcoded strings continue to work until migrated
